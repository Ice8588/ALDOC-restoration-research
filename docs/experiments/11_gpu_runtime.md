# 分層流程的 GPU 常駐、耗時與顯存

在三層 v1.6 的實圖試跑中，Qwen3.8-27B 與 Qwen Image Edit 2511 同時保留在單張 RTX PRO 6000 Blackwell 96 GB 上。VLM、分割與補繪依序執行。SAM3 只在分割時載入，完成後釋放。這個配置讓下一次 QA 可以直接重用 VLM；代價是 SAM 推論時，三組權重與暫存可能同時占用顯存。

| 執行方式 | 權重如何進出 GPU | 證據範圍 |
|---|---|---|
| 獨占式切換 | 獨立 VLM 工作先釋放生成端資源，載入所需模型，批次結束時關閉自己載入的 VLM。 | 歷史執行路徑。尚無在以下九個工作上固定其他條件、只更換常駐策略的速度對照。 |
| VLM 與編輯器常駐、SAM 暫載 | VLM 權重為 BF16。編輯器保留 FP8 mixed Transformer 與 BF16 text encoder。連續呼叫重用相同配置的權重，每次分割重新載入 SAM。釋放配置或改用其他配置時，控制器關閉既有模型並回收快取。 | 下方 v1.6 的 371 份推論紀錄均確認重用這對常駐模型。 |
| SAM 權重也常駐 | 實驗選項可保留 SAM 權重供下次分割使用；每張圖的特徵仍按次處理。 | 九次實圖試跑都使用 SAM 暫載。三模型常駐的全流程速度增益與穩定工作尺寸仍待配對量測。 |

## 三層 v1.6 的逐階段量測

森林、海灘、月夜三張 1536×864 自製插圖各跑三個 seed。VLM 啟用 sampling、關閉 thinking，編輯器使用 20 steps。表中按已留下完整量測的操作計數，包括重試。各階段以 CUDA 同步界定起訖，每約 50 ms 採樣整卡已用顯存，另在階段結束讀值。峰值是各次實測中的最高值，以 GiB（2³⁰ bytes）表示，包含其他常駐權重與 GPU 暫存；短於採樣間隔的尖峰可能漏測。[實驗條件與各場景的拆分結果](10_hierarchical_evaluation.md)

| 單次計時範圍 | 次數 | 耗時中位數（秒） | 整卡已用顯存最高採樣值（GiB） |
|---|---:|---:|---:|
| VLM 呼叫（含規劃、定位或評估） | 260 | 15.32 | 90.48 |
| SAM 完整分割呼叫 | 70 | 31.97 | 94.79¹ |
| └ 載入 SAM | 70 | 28.61 | 89.79 |
| └ 圖像編碼與遮罩解碼 | 70 | 1.54 | 94.79 |
| └ 清理 SAM | 70 | 0.47 | 91.26 |
| 編輯器補繪一個候選 | 41 | 42.09 | 92.20 |

¹ SAM 完整呼叫的時間取外層計時，顯存則取其內外層紀錄的最大值。三個子階段已包含在完整呼叫中。清理時仍會觀測到釋放前的配置；清理**結束時**的整卡已用量中位數為 **86.48 GiB**。這組設定下，一次分割的大部分時間花在載入 SAM。

每格從該次執行程序開始跑分層，計到完成 PNG／PSD 檢查為止，包含程序內的推論等待、重試與匯出。若中斷後接續，此欄只計最後一次程序。九次都輸出部分結果，早停與拆出的層數會改變總時間。各版本的完整可用圖層成本仍缺少對齊工作量與人工評分的比較。

## 雙模型冷載與容量試驗

另一項 1024×1024 的容量試驗先載入兩個模型，再以「VLM → 編輯器 → VLM」連續執行四輪。每輪核對 CUDA 權重儲存位置與型別。配置 A 的常駐權重儲存共 **85.76 GiB**。一次冷載中，VLM 用 20.71 秒、編輯 Transformer 4.88 秒、text encoder 6.22 秒、pipeline 與 VAE 1.08 秒，四段共 **32.89 秒**。這次量測沒有執行 SAM。

| 編輯器配置（皆搭配 Qwen3.8 BF16 VLM） | 完成輪數 | 整卡最高採樣已用量 | 推論觀察 |
|---|---:|---:|---|
| A：FP8 mixed Transformer、BF16 encoder | 4/4 | 91.82 GiB | 20-step 補繪每次 37.01–37.32 秒；最低採樣可用顯存 3.15 GiB。 |
| B：同一 Transformer、預定 FP8 encoder | 0/4 | 94.95 GiB | 載入 Transformer 時 OOM，尚未載入 encoder。當時整卡用量和本程序 PyTorch 保留量相差 36.32 GiB，差額來源未確認。 |

配置 B 尚需在其他顯存占用受控時重測。上述數據衡量硬體容量與執行時間；圖層品質另按辨識、切割及補全評估。[模型與補全實驗分數](01_baselines.md) · [三層架構與各階段審查](../system_evolution.md)
